# 360 Cloud Board — Postman Collection

Full REST API coverage for every route under `src/app/api/**` (77 requests: 74 app
routes + 3 NextAuth Auth-folder requests). Generated by `generate-collection.ts` —
see that file for the endpoint catalogue and regenerate it any time a route's Zod
schema or authz gate changes.

## Setup

1. Import both `360-Cloud-Board.postman_collection.json` and
   `360-Cloud-Board.postman_environment.json` into Postman.
2. Select the **360 Cloud Board — Local** environment (top-right environment
   picker).
3. Make sure the app is running (`npm run dev`, default `http://localhost:3000` —
   matches `baseUrl`).
4. Fill in `testEmail` / `testPassword` in the environment. **The account must
   already exist** — there is no REST signup endpoint; create one via the app's
   `/signup` page first.
5. Open the **Auth** folder and run, in order:
   - **Get CSRF Token** — fetches a token and stores it in `csrfToken` via its
     Tests script.
   - **Login** — signs in with the Credentials provider. Postman's cookie jar
     (on by default in the desktop app, per-domain) then carries the session
     cookie into every other request automatically, as long as you stay on the
     same `baseUrl` domain in the same Postman session.
   - **Get Session** — optional sanity check that you're logged in.
6. Everything else in the collection now works.

## Filling in resource-id variables

Most requests use path variables like `{{teamId}}`, `{{workItemId}}`,
`{{customerId}}`, etc. (see the `variable` array in the collection, or the
environment file — same 18 names). The quickest way to populate them:

1. Run the relevant **create** request from this collection (e.g. "Create Team"
   under Teams, Org Admin required).
2. Copy the `_id` from the JSON response.
3. Paste it into the matching environment variable (e.g. `teamId`).

Nested resources need their parent id set first — e.g. set `teamId` before
creating a Work Item, then set `workItemId` from that response before touching
anything under Work Items > Nested Resources.

If you want requests to capture ids automatically instead of copy/pasting, add
a **Tests** script to a create request, the same pattern the Auth folder's "Get
CSRF Token" request uses:

```js
const data = pm.response.json();
pm.collectionVariables.set("teamId", data.team._id);
```

That's a starting point, not a full automation — this collection is meant for
hand-testing the API, not as a CI test suite.

## Notes

- Every request's description states which `src/lib/authz.ts` gate it requires
  (e.g. Team Admin via `requireTeamRole`, Org Admin, or "any authenticated
  Member").
- Where a field is an enum, the request description lists the allowed values
  (Postman's JSON body editor doesn't support comments).
- File-upload requests (avatar, attachments) use `multipart/form-data` — pick a
  file in Postman's body editor before sending.
